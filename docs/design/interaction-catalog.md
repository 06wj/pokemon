# 生活小戏目录 · v0.1

> 设计提案，与 [玩法主文](living-diorama-gameplay.md) 配套。以下是规则可以形成的可见场景，不是每次必经的固定剧本，也不代表已实现。居民姓名用于说明画面；实际参与者仍由位置、饮食配置、食欲、困意、性格与可达性筛选。

P0 包括四段主戏——水果觅食、篝火、吸水喷水、闻花——以及持续发生的日常生活。P1 扩展已有生活里的变化，包含天气、漂叶、关系记忆等。二十位居民共享场景，不能每次全部接戏；水生居民保持合法水域，饮食偏好是本游戏配置。

所有场景只复用 Idle、Walk、Run、Attack、Happy、Sleep，加朝向、路径、节奏、气泡和少量环境特效。进食用 Idle 与果子缺口、声音表示；缺少移动动画时按主文降级，不让静止模型滑行。新鲜瞬间优先于常态气泡，同屏通常两只、关键时刻最多三只显示。

## 01 · 一枚水果落在脚边｜P0 主戏：水果觅食

- **起因 →** 玩家把水果扔到草地，果子沿短弧线落下，弹两下停住。
- **可见动作 →** 皮卡丘先转头看落点，再走近闻一闻；很饿时会跑上几步。
- **伙伴接戏／分支 →** 伊布可以远远等待；喵喵已经吃饱，只看一眼便继续晒太阳。果子落得离伊布更近时，先来者可能改变。
- **留下变化 →** 果子成为带真实位置与剩余量的食物，最多一只吃、一只近处等待；无人感兴趣时仍留在地面。
- **动画复用 →** Idle → Walk／Run → Idle；水果气泡、落地微尘、朝向变化。不因投掷直接播放进食。

## 02 · 树叶摇了，果子掉了｜P0 日常：摇树与有限果实

- **起因 →** 玩家摇动大树，有成熟果实时一两枚落下；没有时只见叶子晃动。
- **可见动作 →** 走路草看向树冠，可达鸭慢半拍才抬头，落果在地面滚到各自位置。
- **伙伴接戏／分支 →** 有食欲者前来；困倦者继续树荫午睡。一次轻摇通常只是让卡比兽短暂冒出气泡，近处反复大动静才可能让它醒。
- **留下变化 →** 树上成熟数量减少，地面增加对应果实；不会一次摇树凭空生成无限食物。
- **动画复用 →** 树冠摆动与落果特效；居民 Idle／Walk／Sleep，短暂“？”或“Z”。

## 03 · 这次让你先吃｜P0 主戏：争先与礼让

- **起因 →** 皮卡丘和伊布先后靠近同一枚水果，都还没开始吃。
- **可见动作 →** 两只停在不同方向，先看果子，再看对方；其中一只后退半步，另一只走到果子旁。
- **伙伴接戏／分支 →** 半饱的皮卡丘可能让位；更饿时会先吃，伊布则等待或另找食物。不会让每次礼让都由同一只承担。
- **留下变化 →** 进食权只给一只，等待者可随时离开。P0 只改变当下选择，P1 才把这次礼让写入关系记忆。
- **动画复用 →** Idle、转向、短 Walk；礼让后可有 Happy 与一个心形气泡，不需递送或抱起动作。

## 04 · 吃饱了，去别处看看｜P0 日常：进食与满足

- **起因 →** 居民抵达可食水果的接触距离，朝向正确，果子仍有剩余。
- **可见动作 →** 停下来吃，伴随轻轻的咔嚓声，果子出现缺口并逐渐变小；最后开心一下，转身离开。
- **伙伴接戏／分支 →** 中途被打断，余下果子还在原处；旁边等待者可以接着吃。吃饱的原食客不会立刻回头抢下一枚。
- **留下变化 →** 每次咬口只结算一次，食物剩余下降、食欲降低；完全吃完才移除实体。
- **动画复用 →** Idle 的轻微节奏与果子缺口 → Happy → Walk；不需要新增 Eat 动画，不允许隔空消耗。

## 05 · 树荫下的一小块空地｜P0 日常：独立午睡

- **起因 →** 妙蛙种子探索后变困，发现大树安静侧还有阴影和空位。
- **可见动作 →** 脚步慢下来，停下看一眼附近居民，再走进树荫；小“Z”慢慢变成“Zzz”，随后睡着。
- **伙伴接戏／分支 →** 若卡比兽已经占了宽敞位置，妙蛙种子选择另一块空地；果树下正在热闹觅食时，会去更安静的一侧。
- **留下变化 →** 一块真实睡位暂时被占用，困意逐渐缓解；不依赖篝火点燃或天色变暗才能睡。
- **动画复用 →** 慢 Walk → Idle → Sleep；无 Sleep 时安静 Idle，保留休息状态与短暂困意气泡。

## 06 · 挨着安静的伙伴｜P0 日常：同伴午睡

- **起因 →** 胖丁也有点困，发现妙蛙种子已经安静睡在树边。
- **可见动作 →** 它走近，看一看旁边空地，留下身体间距后也睡下。
- **伙伴接戏／分支 →** 位子不够就换到同一片树荫的另一侧；旁边居民正准备离开时，胖丁仍能自行决定留下或换处。
- **留下变化 →** 形成两只各自占位的午睡组合，任何一只都能独立醒来；不是把后来的居民锁进双人动画。
- **动画复用 →** Walk → Idle → Sleep；气泡错开发送，只在新加入或入睡时短暂显示。

## 07 · 不要吵醒它｜P0 日常：绕过睡者

- **起因 →** 伊布的散步路线经过熟睡的卡比兽附近。
- **可见动作 →** 伊布注意到呼噜声，放慢脚步，沿睡位外侧绕过去。
- **伙伴接戏／分支 →** 卡比兽可以继续睡；若近处有更强动静，只短暂改变朝向或醒来看看，不把每次路过都变成叫醒事件。
- **留下变化 →** 路线改变，睡眠仍延续；旁边不被踩踏的小空间显得有人照顾。
- **动画复用 →** Walk 降速与合法绕行，Sleep；醒来采用 Idle，必要时再 Walk 离开。

## 08 · 去溪边喝一口｜P0 日常：饮水

- **起因 →** 卡蒂狗活动一阵后，对附近安全饮水点产生兴趣。
- **可见动作 →** 走到干燥岸边，面对水面停留，水面出现几圈细纹，随后满足地看向四周。
- **伙伴接戏／分支 →** 可达鸭可以在另一侧一起看水；岸位已占用时卡蒂狗等一会儿或换点，不挤进水里。
- **留下变化 →** 短期饮水兴趣下降，居民转回探索或休息；喝水不必消耗整条河的水位。
- **动画复用 →** Walk → Idle → Happy；局部涟漪与水滴气泡，饮水姿态以现有片段和朝向近似。

## 09 · 把水带给花朵｜P0 主戏：吸水、喷水与花开

- **起因 →** 花丛偏干，杰尼龟主动去河内取水。
- **可见动作 →** 在水中停留吸水，上岸调整朝向，再喷出一小道水流；花朵抖动舒展。
- **伙伴接戏／分支 →** 妙蛙种子先到时会停下看花，巴大蝶先到时会绕花飞；皮卡丘可能高兴，也可能被一滴水惊得停住。
- **留下变化 →** 吸水资格只能使用一次，花的湿润与开放度上升，随后缓慢回落；没有先吸水就不能喷花。
- **动画复用 →** Walk → Idle＋drink → Walk → Attack＋splash → Happy；来客用 Walk／Happy。

## 10 · 一口喷嚏，两双眼睛｜P0 主戏：闻花与回应

- **起因 →** 开放的花吸引皮卡丘靠近。
- **可见动作 →** 皮卡丘对着花闻一会儿，通常开心离开，偶尔突然打一个喷嚏，少量花粉飘起。
- **伙伴接戏／分支 →** 巴大蝶避到旁边，妙蛙种子可能开心；没人围观时，皮卡丘也可以自己回头看花再笑一下。
- **留下变化 →** 花粉短暂存在，附近居民各回应一次；正在远处睡觉的卡比兽不受影响。
- **动画复用 →** Walk → Idle → Happy，偶尔 Attack＋pollen；“花”转短促“！”，旁观者 Idle／Walk／Happy。

## 11 · 第一簇火光｜P0 主戏：点火与自主聚集

- **起因 →** 木堆备好，小火龙有兴趣且能到达点火位。
- **可见动作 →** 它走近、面对木堆轻喷火，再退到外围；光落在地面，一两位伙伴转头后走来。
- **伙伴接戏／分支 →** 皮卡丘可能绕着火慢走，六尾只停一会儿；卡比兽赴约后直接外围睡觉，也可能留在树荫继续睡。
- **留下变化 →** 营火持续提供光和暖处，参与者各自离开；点火者中途离场不会让已经燃起的火凭空消失。
- **动画复用 →** Walk → Idle → Attack＋ignite → Walk／Happy；来客 Walk、Happy 或 Sleep，不穿越火心。

## 12 · 果子自己掉下来了｜P0 日常：无输入觅食链

- **起因 →** 一枚树果自然成熟脱落，玩家没有操作。
- **可见动作 →** 果子滚到树荫边缘，喵喵停下脚步看过去；卡比兽仍睡在另一侧。
- **伙伴接戏／分支 →** 喵喵有食欲就走近吃；它已经饱了时，波波可能晚一点才来。没有合适食客也允许果子暂时安静留着。
- **留下变化 →** 树上成熟量减少，地面食物增加，再由真实取食消耗，证明生活不靠玩家不停按按钮。
- **动画复用 →** 落果特效、Idle 转向、Walk／Run、Idle 进食、Happy。

## 13 · 水上的那一小口｜P0 日常：水生觅食

- **起因 →** 配置为可漂浮、可食的水果落入浅水，形成一个缓慢移动的落点。
- **可见动作 →** 角金鱼在水内游近，停在果子旁；鲤鱼王从稍远处转向观察。
- **伙伴接戏／分支 →** 角金鱼开始吃，鲤鱼王可等待或继续游；漂到不可达位置时两者放弃，陆上伊布也不会冲进深水抢食。
- **留下变化 →** 水果位置随缓慢水流更新，消费仍验证真实距离与唯一归属；只影响配置中有此饮食偏好的居民。
- **动画复用 →** 复用模型可用的 Walk／Run 表示游动，Idle 表示停驻进食；水纹和水果缺口补充语义。

## 14 · 醒来，换个方向看看｜P0 日常：睡醒与恢复

- **起因 →** 一段安稳休息后困意缓解，或天光变化与作息共同促使居民醒来。
- **可见动作 →** 皮皮结束睡眠，静静看一会儿周围，再开心一下，离开树荫。
- **伙伴接戏／分支 →** 胖丁可以继续睡；皮皮看见别处花开就去观察，有食欲则找果子，不要求醒来统一排队吃饭。
- **留下变化 →** 原睡位释放，居民重新探索；改变清晨／黄昏也不会让二十只同一帧齐醒。
- **动画复用 →** Sleep → Idle → Happy → Walk，短暂消退的“Z”代替额外起身或伸懒腰片段。

## 15 · 今天这块暖石不错｜P0 日常：选择晒暖处

- **起因 →** 喵喵或六尾想安静停一会儿，附近暖石有空位。
- **可见动作 →** 它走上合适的平整位置，朝着光停住，过一会儿再换个朝向。
- **伙伴接戏／分支 →** 卡蒂狗路过可能停在外侧；位置太挤时继续去散步，不把原居民推下石头。
- **留下变化 →** 暖石形成与营火不同的安静聚集处，休息者占位直到自行离开。
- **动画复用 →** Walk → Idle／Sleep，慢转向、暖色光与短暂温暖气泡。

## 16 · 追的是影子｜P1 扩展：轻微追逐

- **起因 →** 巴大蝶经过明亮草地，移动的影子被好奇的皮卡丘看到。
- **可见动作 →** 皮卡丘追着影子跑，巴大蝶轻轻改变方向。
- **伙伴接戏／分支 →** 快到卡比兽睡位时，两只一起慢下来；巴大蝶疲惫时不继续游戏，皮卡丘停住看看再自己离开。
- **留下变化 →** 一次短游戏增加疲惫，随后可能转入饮水或午睡，不能无限循环追逐。
- **动画复用 →** Walk／Run、转向、Happy，飞行角色沿自身合法路径移动，不新增抓扑动画。

## 17 · 雨后的翅膀｜P1 扩展：烘干与保持距离

- **起因 →** 雨停后巴大蝶翅膀显得湿润，小火龙附近有一小块干暖地。
- **可见动作 →** 巴大蝶靠近外围停留，小火龙转头看它；细小水珠渐渐减少。
- **伙伴接戏／分支 →** 太热时巴大蝶自己退远，足够干燥就飞回花丛；小火龙先离开时，它改找其他干燥处。
- **留下变化 →** 湿润状态缓解，巴大蝶恢复探索；P1 可记住这次舒服的靠近，提高下一次选择概率。
- **动画复用 →** Walk／Idle／Happy，水珠淡出与距离变化，不需要扇翅专用片段或身体接触。

## 18 · 桥头互相让一步｜P1 扩展：可读的让路

- **起因 →** 皮卡丘和杰尼龟在桥头相向而行，侧边有可退让位置。
- **可见动作 →** 两只停住，一只退到桥头侧面，另一只通过后回头看一眼。
- **伙伴接戏／分支 →** 谁更赶路、谁更愿意退让影响先后；通路仍堵住时各自等待或另择目标，不无限互相礼让。
- **留下变化 →** 桥面恢复畅通，双方原有生活继续；可记录一次“桥边的偶遇”。
- **动画复用 →** Walk → Idle → 短 Walk → Happy；朝向与站位表达交流，不需要挥手。

## 19 · 倒影忽然不见了｜P1 扩展：围观水面

- **起因 →** 皮卡丘在安全岸位观察水中倒影，角金鱼从旁游过。
- **可见动作 →** 水纹打散影子，皮卡丘短暂“！”，再转向水纹中心。
- **伙伴接戏／分支 →** 可达鸭可能凑来一起看，角金鱼也可能继续游远；水面恢复后，两只岸上居民又看见各自的影子。
- **留下变化 →** 短时水纹从一位居民传到另一位的注意力，不制造永久资源收益。
- **动画复用 →** Idle、转向、Walk／Happy；倒影与涟漪负责视觉变化，所有角色保留合法岸位／水域。

## 20 · 呼噜里的小合奏｜P1 扩展：声音与睡眠分支

- **起因 →** 卡比兽规律打呼，杰尼龟在附近停留。
- **可见动作 →** 杰尼龟在呼噜空隙叫一声，皮卡丘随后跟着节奏开心晃动。
- **伙伴接戏／分支 →** 声音很轻时卡比兽继续睡；越闹越近才可能醒来，两只随即停住，音符气泡一个个收起。
- **留下变化 →** 卡比兽可能换处继续睡，也可能很快又打呼；两位访客不必立即重演，留出安静冷却。
- **动画复用 →** Sleep、Idle、Happy；叫声可配短 Attack 或 Idle 与音效，无攻击含义。

## 所有场景共同的收尾要求

水果被吃完、对象离开、路线不可达、演员被移除、动作超时都要结束等待并释放站位；已经发生的消耗与环境变化按实际状态保留。仅准备好、未发出的效果在中断时取消。瞬时事件带有效期与去重标识，开心回应不重新触发整条主戏。清空场景重置临时居民、资源和事件，已收藏照片与发现记录按主文保留。

无动画片段不等于无生活：可以用现有朝向、静态停留、短气泡与环境反馈完成近处回应。验证重点始终是玩家是否看见“它需要什么、走去哪里、发生了什么、谁注意到了、之后有何不同”，而不是为目录里每一张卡增加一套新动画。
